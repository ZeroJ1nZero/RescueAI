# Orin Nano 8GB 기반 공간지도·물체 표시 실험 및 구현 계획

작성일: 2026-10-22

## 1. 목표와 현재 범위

센서를 구매하기 전에 공개된 실제 실내 RGB·깊이·IMU 기록을 Orin Nano 8GB에서 재생하여, 공간지도 생성과 물체 위치 표시 파이프라인을 검증한다. 가상의 거리나 온도를 임의로 입력하는 목업이 아니라 실제 센서 측정 기록의 오프라인 재처리 실험이다.

완성 결과는 ① 관측된 공간의 3D 점군 ② 바닥 기준 2D 장애물 지도 ③ 촬영자의 추정 이동 경로 ④ 물체 라벨·좌표·근거 프레임 ⑤ 선택적인 Gemma 설명이다. 정돈된 건축 도면이나 완전한 3D 모델 생성까지를 완료 기준으로 삼지 않는다.

이번 실험에는 열화상·온도·소방 위험 판정, 가상환경 제작, 모바일 앱 제작, 운영 서버 API 구현을 포함하지 않는다. 실제 Gemini 2의 호환성·센서 오차·착용 상태 성능은 구매 후 별도 평가한다. 현재 실행·구현 완료를 보고하는 문서가 아니라 구현할 실험 계획이다.

## 2. 장비와 실행 조건

| 구성 | 역할 | 조건 |
|---|---|---|
| Orin Nano 8GB | 데이터 재생, 위치 추정, 지도 생성, 객체 추론 | 기존 보드·정상 전원·냉각 사용 |
| SSD | 데이터셋과 실험 결과 저장 | 기존 저장장치 활용, 실제 여유 공간 확인 |
| 데스크톱 | 결과 파일을 옮겨 검수 | Orin 처리 실험과 데스크톱 성능을 분리 |
| 공개 실측 데이터 | 가상 센서 입력 대신 사용 | RGB·깊이·보정·IMU·시각 정보 확인 |

처음에는 Orin에서 지도 처리를 단독 실행한다. Gemma·시각화·객체 탐지를 한꺼번에 실행하지 않는다. Orin에서 실행한 프로세스와 데스크톱에서 실행한 프로세스를 실험 기록에 명시한다.

준비 시 JetPack/L4T, Ubuntu, CUDA, ROS 2 버전, 보드 전력 모드, 모델 버전, git commit을 기록한다. 실행 환경을 확인하기 전 최신 버전 설치나 운영체제 재설치를 전제로 하지 않는다. 호환 가능한 ROS 2·패키지 버전을 선택하고 고정한다.

## 3. 입력 데이터 선정

1순위는 OpenLORIS-Scene의 office 계열 시퀀스이다. D435i의 RGB, RGB에 정렬된 깊이, 가속도, 각속도와 센서 보정 정보를 사용한다. 짧은 구간에서 시작해 동일 시퀀스의 긴 구간과 다른 환경으로 확대한다.

해당 데이터는 약 1m 높이의 바퀴형 로봇에서 수집되었다. 보행 바디캠의 큰 흔들림·회전·착용 높이 변화를 대표하지 않는다. 데이터셋 정답 경로는 office에서 모션 캡처, 다른 일부 환경에서는 오프라인 LiDAR SLAM으로 얻은 기준값이므로 출처 차이도 기록한다.

다운로드한 파일의 실제 토픽·파일 형식·프레임·시간 범위를 조사한다. 기존 bag이 현재 ROS 2에서 바로 재생된다고 가정하지 않는다. ROS 1 bag 등은 변환하거나 데이터 어댑터로 읽고, 이미지·IMU·보정값 보존 여부를 확인한다.

### 입력 정규화

| 입력 | 내부 표현 | 필수 확인 |
|---|---|---|
| RGB | 이미지, timestamp, camera_id | 색상 순서, 해상도, 렌즈 보정 |
| Depth | 부동소수 m 단위 깊이, timestamp | 단위·무효값, RGB 정렬 여부 |
| IMU | 가속도 m/s², 각속도 rad/s, timestamp | 중력 포함 여부, 축 방향, 보정 |
| CameraInfo | 내부 파라미터·왜곡·해상도 | 정렬된 깊이에 해당하는 파라미터 |
| Extrinsics | 카메라↔IMU 강체 변환 | 변환 방향과 좌표계 |
| Reference trajectory | 평가 전용 경로 | 시간·좌표계 정합, 사용 목적 분리 |

OpenLORIS D435i 깊이는 공식 설명상 uint16 값에 0.001을 곱해 m로 변환한다. 다른 데이터나 실제 센서에 이 값을 그대로 적용하지 않고 각각 확인한다. 깊이를 임의로 컬러화한 이미지는 거리값 대신 사용하지 않는다.

## 4. 처리 구조와 기술 선택

실측 기록 재생 → 시각·좌표 정렬 → 카메라 위치 추정 → 깊이 누적 → 3D 점군·2D 격자 → 객체 검출·3D 위치 연결 → 파일 저장 → 선택적 Gemma 설명.

### 기본 구현

- ROS 2: 센서 메시지와 시뮬레이션 시각 전달. 재생 데이터를 사용하는 모든 노드에 동일한 재생 시각을 적용한다.
- RTAB-Map/rtabmap_ros: RGB-D 위치 추정과 지도 생성 기준선. 사용 노드와 고정 버전을 기록한다.
- IMU 필터: 가속도·각속도에서 자세를 계산하고, RTAB-Map이 사용하는 중력 방향 제약을 비교한다. 자기계가 없으므로 절대 방위 정확성을 가정하지 않는다.
- 경량 객체 검출기: YOLO nano급 사전학습 모델을 후보로 삼고, 실제 지원 클래스와 Orin 환경을 확인한 뒤 버전을 고정한다. 처음에는 저해상도·배치 1·낮은 추론 빈도로 실행한다.
- Python 노드: 데이터 어댑터, 객체 깊이 추출, 좌표 변환, 관측 기록·지표 저장.
- Gemma 3 4B: 지도·객체 처리 종료 후 선별 프레임과 객체 기록을 해석한다. 좌표·거리 생성은 담당하지 않는다.

RTAB-Map SLAM의 imu 입력은 미리 계산된 orientation을 중력 제약에 사용하는 구성이며, raw IMU를 넣었다고 완전한 Visual-Inertial Odometry를 구현한 것으로 표현하지 않는다. 완전한 시각·관성 융합이 필요해지면 RGB-D-inertial 입력을 지원하는 ORB-SLAM3 구성 등을 별도 실험으로 검토한다.

nvblox는 추가 후보이다. 깊이와 카메라 pose로 공간을 재구성하는 역할이며 위치 추정을 대체하지 않는다. 첫 구현부터 RTAB-Map과 nvblox를 모두 도입하지 않는다. 필요성이 확인되면 기준선과 비교한다.

## 5. 순차 실험

| 실험 | 입력·조건 | 목적 | 결과 |
|---|---|---|---|
| E0 입력 점검 | RGB·정렬 깊이·IMU·보정 | 단위·시각·축·깊이 정렬 검증 | 프레임 미리보기, IMU 그래프, 누락 통계 |
| E1 RGB-D 기준선 | RGB+Depth, 정답 pose 미사용 | 위치 추정·지도 생성 확인 | 추정 경로, 3D 점군, 2D 격자 |
| E2 IMU 자세 제약 | E1과 동일 구간+IMU 필터 자세 | 중력 정렬과 추적 성능 변화 비교 | 경로 오차, 기울기, 실패 구간 |
| E3 물체 지도 표시 | E1 또는 E2 결과+검출기 | 영상 속 물체를 지도 좌표에 연결 | 관측 JSONL, 2D/3D 라벨 |
| E4 처리 부하 | 동일 입력·지도 설정, 객체 추론 빈도 변경 | Orin 처리량과 메모리 확인 | 처리시간·누락·RAM·GPU 로그 |
| E5 Gemma 후처리 | 선별 프레임+관측 기록 | 근거 기반 장면 설명 평가 | 설명·근거 ID·오판 기록 |

E0는 30~60초 구간, E1부터는 우선 1~2분 구간으로 시작한다. 이는 초기 실험 범위이며 검증 성공을 뜻하지 않는다. E1/E2는 같은 구간·해상도·전력 모드로 각각 3회 실행해 반복 편차를 기록한다.

기록 재생 속도는 처음에는 0.25배 등 낮은 속도로 시작하되 센서 timestamp와 IMU 샘플 간격을 변경하지 않는다. 입력을 천천히 처리해 알고리즘이 동작하는지 먼저 확인한다. 원속도 처리는 별도 부하 실험이다. 처리량 때문에 임의로 프레임을 건너뛴 경우 생략 정책과 수를 기록한다.

### 정답 경로 사용 규칙

위치 추정이 막히면 정답 경로로 깊이 누적·물체 투영만 검증하는 보조 실험을 수행할 수 있다. 이 결과에는 반드시 '기준 pose 입력 공간 재구성'으로 표시한다. SLAM 성공 결과와 합치지 않는다. RGB·깊이·IMU만 사용하는 실험에서 데이터셋의 바퀴 odometry나 LiDAR를 암묵적으로 사용하지 않는다.

## 6. 물체 위치 계산과 지도 표시

RGB 검출 박스만으로 3D 위치가 정해지지 않는다. RGB에 정렬된 깊이와 해당 카메라의 내부 파라미터를 결합한다.

1. 검출 영역 또는 분할 마스크 안의 무효 깊이·먼 배경을 제거한다.
2. 유효한 깊이 군집으로 대표 3D 점이나 물체 표면 점군을 추정한다.
3. 픽셀 (u,v), 깊이 Z, 초점거리 fx/fy, 주점 cx/cy에 대해 X=(u-cx)Z/fx, Y=(v-cy)Z/fy를 적용한다.
4. 관측 시각에 해당하는 카메라→지도 변환으로 지도 좌표를 계산한다. pose가 없거나 시각 차이가 한도를 넘으면 좌표를 만들지 않는다.
5. 좌표·라벨·근거 이미지·관측 시각을 함께 저장한다.

초기 박스 기반 위치는 물체의 중심·전체 부피가 아니라 보이는 표면의 대표 위치 근사치로 명시한다. 유효 깊이 비율과 분산을 함께 기록한다. 사람 등 이동 물체는 정적 지도와 별도 관측 레이어에 둔다.

처음에는 관측별 ID만 부여한다. 이후 같은 클래스·거리·관측 시각·시각 특징을 이용해 대응을 추가하되, 가까운 동일 종류의 물체를 무조건 하나로 합치지 않는다. 고유 물체 수는 대응 기능을 검증한 뒤 보고한다.

루프 폐쇄로 지도 좌표가 보정될 수 있다. 관측 당시 카메라/키프레임 좌표와 연결 정보를 남겨 최종 pose로 물체를 다시 투영한다. 이전 좌표에 마커만 남겨 지도와 어긋나는 것을 방지한다.

### 2D·3D 출력

- 3D: 원점·축·단위가 정의된 점군, 카메라 경로, 물체 라벨.
- 2D: 중력/바닥 정렬 후 초기 5cm 격자 후보를 사용한다. 바닥·천장을 제외할 높이 범위를 명시한다. 문턱 등 낮은 장애물의 누락도 확인한다.
- Occupancy는 occupied/free/unknown을 구분한다. 점이 없다는 이유만으로 통행 가능한 free로 채우지 않는다. 유효한 센서 관측선으로 확인한 영역을 이용한다.
- 전체 영역의 높이를 무조건 2D로 투영하지 않는다. 다층·계단 환경은 첫 실험에서 제외하고 한 층 구간부터 시작한다.

## 7. Gemma 실험

지도 생성·위치 추정이 종료된 후 Gemma를 로드해 메모리 경쟁을 줄인다. 선택한 프레임, 검출 객체 ID, 계산된 거리·좌표, 근거 시각을 입력한다. 관측 기록을 사람이 읽을 수 있는 설명으로 바꾸는 용도이다.

Gemma가 위치를 새로 생성하거나 이미 계산된 좌표를 변경하지 못하게 한다. 온도는 입력이 없으므로 null을 유지한다. 결과 설명의 각 항목을 근거 관측 ID에 연결하고, 모르는 경우 판단 불가를 허용한다. 설명에 모델 자체의 자신감 숫자를 부여해 정확도처럼 쓰지 않는다.

평가는 사람이 표시한 대표 프레임으로 물체 종류·설명의 근거 일치율, 없는 물체 추가, 숫자 변경, 판단 불가 비율을 확인한다. Gemma 분석이 끝나야 지도가 저장되는 구조로 만들지 않는다.

## 8. 소프트웨어 구성과 산출물

| 모듈 | 책임 |
|---|---|
| dataset_adapter | bag/파일 로딩, 정규화, 보정값·단위 확인 |
| replay | 원본 시각 보존, 재생 속도, ROS 메시지 발행 |
| localization | RGB-D pose, IMU 자세 제약 설정, 상태 기록 |
| mapping | 깊이 누적, 점군, 점유 지도 내보내기 |
| detection | 객체 박스/마스크와 검출기 점수 |
| object_projection | 깊이·pose 결합, 관측 위치·품질 기록 |
| annotation | Gemma의 근거 연결 설명, 원본 응답 보존 |
| export | 파일 목록, 지도·객체·메타데이터·지표 저장 |

세션별 결과: session.json, calibration.json, trajectory.csv, object_observations.jsonl, objects_final.json, map_3d.ply, map_2d.png, map_2d.yaml, metrics.json, tegrastats.log, failures.jsonl, 근거 프레임, report.md. map_2d.yaml에는 해상도·원점·축·점유값 해석을 포함한다.

관측 기록 필드: session_id, observation_id, timestamp, image_ref, class_label, bbox/mask_ref, camera_frame, point_camera_m, pose_ref/keyframe_id, point_map_m, valid_depth_ratio, depth_dispersion, position_status, detector_model_version. 온도는 null이다. 투영 실패 시 point_map_m을 null로 남기고 실패 이유를 저장한다.

## 9. 평가 기준

| 항목 | 측정·해석 |
|---|---|
| 경로 오차 | 기준 경로와 시간·좌표계를 맞춘 ATE/RPE. RGB-D는 m 단위 척도를 유지하고 스케일 보정으로 오차를 숨기지 않음 |
| 추적 유지 | 입력 구간 중 pose 산출 비율, 추적 상실 횟수·시간, 재초기화 구간 |
| 물체 위치 | 동일 정적 물체의 반복 관측 분산, 수동 대응 오율, 깊이 부족으로 위치 미산출 비율 |
| 지도 품질 | 바닥 정렬·벽 중복·루프 폐쇄 전후 어긋남. 기준 3D 지도가 없으면 절대 지도 정확도 수치를 주장하지 않음 |
| 처리량 | 영상 길이/실제 처리시간, 지연 p50/p95, 입력·처리·생략 프레임 수 |
| 자원 | tegrastats의 RAM·CPU/GPU·온도, swap, OOM 발생 여부 |
| 설명 품질 | 수동 정답 기준 물체/설명 일치, 근거 없는 객체·숫자 생성 |

실행마다 dataset 구간, 전력 모드, 패키지·모델 버전, 설정 해시를 남긴다. IMU 결과가 개선되지 않아도 삭제하지 않고 동기화·보정·알고리즘 역할을 검토한다. 데이터셋에 물체 위치 정답이 없다면 반복성 평가는 가능하지만 절대 물체 위치 정확도를 입증한 것은 아니다.

초기 완료 조건은 지정 구간에서 실패가 기록되고 결과가 재현되며, 경로·지도·대표 물체 관측을 근거 이미지로 대조할 수 있는 것이다. ATE·처리 FPS·정확도 수치는 실제 기준선 실행 후 목표를 정한다. 측정하지 않은 실시간 성능을 보장하지 않는다.

## 10. 구현 일정과 단계별 통과 조건

아래는 4주 배치안이며 작업량을 보장하는 일정은 아니다. 환경 구축과 보정 문제에 따라 조정한다.

| 기간 | 작업 | 통과 조건 |
|---|---|---|
| 1주차 | 환경 기록, 데이터셋 확보, 어댑터·재생, E0 | 깊이 단위·시각·카메라 보정 확인, RGB/Depth/IMU 재생 |
| 2주차 | E1 공간지도 기준선, E2 IMU 자세 제약 비교 | 경로·점군·2D 지도 저장, 동일 조건 비교 결과 |
| 3주차 | 검출기·물체 좌표 투영, 근거 이미지·파일 내보내기 | 대표 객체의 실제 깊이에 근거한 지도 표시 |
| 4주차 | Orin 부하 측정, Gemma 후처리, 반복 실험·보고서 | 지표·제약·실패 사례·재현 절차 정리 |

E1이 실패하면 객체 탐지·Gemma를 먼저 붙이지 않는다. 환경 구축과 입력 변환에 문제가 있으면 짧은 구간을 PC에서 입력 검증하되, Orin에서 성공한 결과와 분리해 보고한다.

## 11. 물리 이동 및 향후 서버·앱 연결

원시 데이터와 결과는 SSD에 저장한다. 현장에서 인터넷으로 영상을 업로드하는 방식은 이번 계획에서 요구하지 않는다. 처리 후 안전 제거한 SSD를 서버/데스크톱으로 옮기고 파일 목록·해시를 확인한다.

Orin 자원이 부족하면 지도와 검출을 서로 다른 패스로 처리할 수 있다. 이 경우 오프라인 다중 패스 처리로 표시하고 동시 실시간 실행이라고 보고하지 않는다. Gemma는 기본적으로 별도 패스이다.

후속 API는 동일 session_id·지도 버전·좌표계를 기준으로 2D 지도, 3D 파일, 물체 목록을 제공한다. 모바일/데스크톱은 각각 서버를 조회한다. 이번 실험에서는 이 API를 실제 구축하지 않고, 전달할 파일과 스키마를 확정한다.

## 12. 장비 구매로 넘어가는 기준

센서 기록으로 지도·좌표 변환·파일 재생이 동작하고, 실패 원인이 데이터·보정·알고리즘·자원 중 어디에 있는지 분리할 수 있으면 Gemini 2 구매 후 실제 획득 노드를 연결한다. 데이터셋 입력 어댑터를 실제 센서 입력으로 교체하되 깊이 단위·RGB 정렬·IMU 보정을 다시 검증한다.

장비가 없을 때 얻을 수 있는 성과는 소프트웨어 파이프라인과 Orin 처리 성능의 근거이다. Gemini 2 드라이버·USB 대역폭·전원·착용 흔들림·실내 조명 성능은 이 실험으로 대체할 수 없다.
